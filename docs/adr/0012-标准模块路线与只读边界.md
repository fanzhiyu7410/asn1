# ADR-0012：标准模块路线、展平自包含策略与只读边界

- 状态：已确认（用户批准，2026-11-06）
- 日期：2026-11-06
- 关联：[ADR-0009](0009-分层与独立模块策略.md)、[ADR-0007](0007-模式层边界.md)、[能力范围](../03-ASN1能力范围.md)、[里程碑](../09-里程碑与分期.md)、[描述表格式](../11-描述表格式.md)

## 背景

ADR-0009 确定分层：核心零领域知识，`asn1-pkix`、`asn1-cms`、`asn1-pkcs` 为独立包，模块只依赖核心、模块之间不互相依赖。实际推进中还需要回答三个问题：

1. 三个标准模块按什么顺序做、每个模块做到什么粒度；
2. CMS 需要 PKIX 的 `AlgorithmIdentifier`、`Extension`、`Attribute` 等类型时，如何在不新增模块间依赖的前提下复用；
3. 第一版模块是否承担密码学语义（验签、解密、密钥运算）。

同时，ADR-0009 与 ADR-0007 中“一期必须支持 `IMPORTS` 与单参数参数化”的表述与已落地的展平输入路线冲突：`asn1c` 一期输入是自包含展平模块，`IMPORTS` 与参数化只报诊断。需要一并收敛。

## 决策

### 1. 路线顺序

1. `asn1-pkcs` 先做：PKCS#8 + PKCS#1，只读。
2. `asn1-cms` 后做。

### 2. 切片

| 顺序 | 内容 | 阶段 | 边界 |
| --- | --- | --- | --- |
| 1 | PKCS#1（RFC 8017）+ PKCS#8（RFC 5208 及相关勘误） | 一期续 | 只读结构 |
| 2 | PKCS#10（RFC 2986） | 紧接第 1 项 | 只读结构 |
| 3 | PKCS#12（RFC 7292） | 后置 | 只读结构 |
| — | PKCS#7 | 不单独做 | 归入 `asn1-cms` |

### 3. 模块隔离与 CMS 的展平自包含

- ADR-0009 的“模块只依赖核心、模块之间不互相依赖”**保持不变**。
- `asn1-cms` 需要的 PKIX 类型，在 `asn1-cms` 自己的展平模块中**复制所需类型**（如 `AlgorithmIdentifier`、`Extension`、`Attribute`），不新增 `asn1-cms → asn1-pkix` 依赖。
- 代价：
  - CMS 描述表更大，同一类型在 pkix 与 cms 各有一份定义；
  - 类型级对账要按模块分别做，缺陷可能需要在两份定义中分别修复；
  - 产物体积与符号存在重复。
- 缓解：
  - 每个模块维护自包含展平文件与类型级对账表，逐类型对齐 RFC 原文；
  - 以 RFC 原文为唯一事实来源，不共享实现代码，只共享核心公共 ABI；
  - 复制范围限定为 CMS 结构实际引用的类型，不做整模块照搬。

### 4. 只读边界

第一版所有模块只读，不做密码学语义的写：

- `asn1-cms`：只读 `ContentInfo` / `SignedData` 结构；不验签、不摘要、不解密、不校验证书链。
- `asn1-pkcs` 的 PKCS#8：只读 `PrivateKeyInfo` / `EncryptedPrivateKeyInfo` 结构，不解密。
- `asn1-pkcs` 的 PKCS#1：只读 ASN.1 结构；不做 RSA 运算、填充、签名、加密；填充参数仅作为 `ANY` 保留。
- `ANY` 字段只返回原始 TLV，由调用方按 OID 二次解析。

### 5. 展平输入与工具边界

`asn1c` 一期输入是自包含展平模块，不依赖 `IMPORTS` 与参数化：

- 遇到 `IMPORTS` 报 `ASN1C_E_IMPORT_UNRESOLVED`(9007)；
- 遇到参数化定义/实例化报 `ASN1C_E_UNSUPPORTED_CONSTRUCT`(9006)；
- 跨模块导入、参数化展开与直接消费原始 RFC 模块留后续，不阻塞本 ADR 的模块切片。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| `asn1-cms` 链接并依赖 `asn1-pkix` 复用类型 | 引入模块间依赖，违反 ADR-0009；模块版本被迫耦合，安装依赖链变长，任一模块升级会牵动另一个 |
| 把 PKIX 公共类型下沉到核心 | 核心被证书领域概念污染，违背核心零领域知识原则 |
| CMS 与 PKIX 共用一个跨模块“公共类型包” | 实质仍是模块间依赖，且新增第四个包与版本矩阵，收益低于复制成本 |
| 第一版就提供解密/验签/密钥运算 | 引入密码学实现与安全边界，超出 ASN.1 库定位；错误更容易被误用为安全结论 |

## 后果

- `docs/03`、`docs/09`、`docs/01`、模块 README 必须同步本 ADR 的顺序、切片与只读边界。
- `asn1-pkcs` 第一切片交付 PKCS#8 + PKCS#1 只读结构访问；PKCS#10 已按第 2 项落地；PKCS#12 后置，PKCS#7 归 CMS。
- CMS 实现时必须自带展平模块，并附类型级对账表；CI 需分别校验各模块的生成表。
- ADR-0009 决策 6、ADR-0007 决策 6 与 ADR-0008 D20 中“一期必须支持 `IMPORTS`/参数化”的表述由本 ADR 修订。
- 新增密码学语义能力必须新开 ADR，不得在模块内静默扩展。
