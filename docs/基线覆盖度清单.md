- **已覆盖**：有明确设计、边界与验收口径。

## 4. 自评

**文档覆盖度：约 97%。**

计算方式：文档基线交付主题 = 第 1 节 6 项 + 第 2 节 27 项，共 33 项；“已覆盖”计 1 分，“部分覆盖”计 0.5 分。当前 32 项已覆盖、1 项部分覆盖（C/C++ 真实 API 示例），加权 32.5/33 ≈ 98.5%；按部分覆盖计 0 分的保守口径为 32/33 ≈ 97.0%，取较低值约 97%。

第 3 节记录的是编码阶段细化项与后续阶段能力（CER/PER、性能阈值、本地化等），不属于“文档基线”交付分母，因此不拉低本阶段覆盖度；它们会在实现阶段逐项转为设计或代码。

按保守口径，剩余缺口不阻塞一期开工：

1. `asn1_schema.h` 与 `asn1_encode.h` 已落地；`asn1c` 的 `IMPORTS`、参数化展开与模块真实语义仍随一期后续轮次补齐。
2. C/C++ 示例目前只有可编译占位，真实 API 示例随一期补齐。
3. 模块公共 API 的具体函数在一期（pkix）与二期（cms/pkcs）设计。
4. `asn1c` 命令行参数与诊断输出已冻结（见[描述表格式](11-描述表格式.md)第 12.1、16 节）；诊断消息的英文措辞仍属实现期细节。描述表 CRC32C 校验和已冻结（见同文第 2.1 节）。
5. 性能基准阈值、打包脚本、CI YAML 等工程细节随实现补齐。
