# 测试与验证策略

## 1. 目标

证明三件事：

1. **正确性**：BER/DER 的结构解析、DER 编码与 C ABI 行为符合规范与文档。
2. **鲁棒性**：任意输入不崩溃、不泄漏、不越界、不无限递归，失败时干净返回。
3. **兼容性**：与主流实现的编码结果、解码结构一致；ABI 在版本演进中保持向后兼容。

| C ABI 测试 | 用 C 编译并调用公共头文件；句柄生命周期、错误查询、缓冲区释放 | C99 测试程序 + CTest | 一期起 |

## 3. 单元测试框架：doctest

已确认选型：**doctest**（单头文件、轻量、无外部依赖、支持无异常配置）。

- 版本固定，编码阶段 vendored 到 `tests/third_party/doctest/`，避免 CI 网络依赖；当前仓库尚无该源码，清单中登记为计划引入。
- 测试目标同样以无异常配置为主；doctest 使用 `DOCTEST_CONFIG_NO_EXCEPTIONS`。只有框架无法支持时才允许在测试目标局部放开异常/RTTI，且不得传播到库目标。
- 测试按模块组织：

```text
tests/
├─ unit/       标签、长度、节点、值读取、错误、内存
├─ c_api/      C 语言 ABI 测试
├─ asn1c/      工具端到端（生成描述表 → 加载 → 解码/编码）
├─ pkix/       模块端到端：真实证书字段访问、ANY 形态、安装后独立消费
├─ pkcs/       模块端到端：PKCS#8/#1/#10 真实样本字段与负例
├─ cms/        模块端到端：CMS ContentInfo / SignedData 真实样本字段与负例
├─ conformance/ DER/BER 向量与差分数据
├─ fuzz/       libFuzzer harness
├─ differential/ 差分工具（`asn1_dump`）与 `diff_asn1.py`（OpenSSL `asn1parse` / asn1tools）
├─ embedded/   静态池最小用例（宿主注册 CTest，交叉编译只构建）
└─ support/    测试向量加载、临时分配器、断言辅助
```

- 当前实际目录即上述十一项（`tests/smoke/` 已并入 `unit/` 并删除）。骨架阶段每个目录至少注册一个 CTest 用例，使用无第三方依赖的最小 C 程序与 `tests/support/check.h` 断言；doctest 与 libFuzzer 在登记后接入。
- CTest 注册每个测试可执行文件；失败输出包含输入文件名、偏移与错误码。
- 测试不依赖当前工作目录；向量路径由 CMake 以编译定义传入。

### 3.1 测试依赖的许可约束

- 测试与工具依赖仅接受 MIT、BSD-2-Clause、BSD-3-Clause、Apache-2.0（含 LLVM 例外）等宽松许可；禁止 GPL/LGPL/AGPL 或许可不明代码。
- doctest（MIT）为测试框架；libFuzzer（Apache-2.0 WITH LLVM-exception）随编译器工具链提供，不进入仓库、不随产物分发。
- 任一新增测试或 fuzz 依赖必须先登记到[第三方依赖与许可证清单](第三方依赖与许可证清单.md)，再进入代码。
- CI 检查点：`deps-license` job 运行 `python scripts/check_third_party.py`；发现未登记引用、禁止许可或清单格式错误即失败。
- OpenSSL `asn1parse`、Python `asn1tools` 属于 CI 外部参照，不链接、不分发，不计入依赖登记。

## 4. 一致性验证

### 4.1 规范向量

- 覆盖 BER 确定/不定长、DER 最短形式、高标签号、SET/SET OF 排序、BOOLEAN 规范值、OID 弧编码、字符串类型、边界长度（127/128/255/256/65535）。
- 覆盖错误向量：截断、长度溢出、EOC 缺失、DER 不定长、非最短长度、尾随字节、非法 BOOLEAN。
- 向量以“输入字节 + 期望结构 + 期望错误码”形式保存；期望值不依赖库自身实现生成。

### 4.2 差分与互操作

- **OpenSSL**：使用 `openssl asn1parse -inform DER/BER` 解析同一输入，比对标签层级、内容长度与偏移。仅作为外部参照，不作为运行时依赖。
- **Python asn1tools**：对公开模式生成 DER 向量，验证库对通用 DOM 的读取；模式相关语义不在基线比对范围。
- **往返不变性**：对合法 DER 输入，`decode → encode` 输出应与输入字节完全相同（规范 DER）；不等时记录差异并归类为解码宽松或编码规范化问题。
- **逐样本留档**：差分脚本可用 `--report` 与 `--report-json` 输出每个样本的逐条对照记录（样本名、双方偏移/层级/TLV 头长/内容长/形态、结论与往返结果）。Markdown 版本检入 `tests/differential/differential-report.md`，CI 重新生成后要求逐字节一致，并作为 artifact 上传 JSON 版本；记录不含工具版本与时间戳，本地复跑可重现同一份文件。样本清单覆盖 PKIX 证书、PKCS#8/#1/#10 与 CMS ContentInfo/SignedData（attached、detached、无证书、多证书、subjectKeyIdentifier sid）。
- 差分测试不进入默认构建；CI 的 `differential` job 显式启用。

## 5. 模糊测试

libFuzzer harness（一期起）：

| Harness | 输入 | 断言 |
| --- | --- | --- |
| `fuzz_decode_der` | 任意字节，DER 严格模式（覆盖 `NON_CANONICAL` 分支） | 不崩溃、不泄漏；成功则树结构自洽 |
| `fuzz_decode_ber` | 任意字节，BER 模式（含不定长） | 同上；深度/节点预算生效 |
| `fuzz_reader` | 任意字节分块喂给 reader（buffer + `_with_schema` 两路径） | 与 buffer 解码结果等价或同样失败 |
| `fuzz_schema_decode` | 任意字节 + 固定 schema（PKIX 表 + 覆盖各 kind/约束的小表，均与解码上下文同源） | 成功解码的树自洽；未知字段保留/`STRICT` 报错、ANY 三形态、EXPLICIT/IMPLICIT 剥壳、约束通过/失败均不崩溃 |
| `fuzz_roundtrip` | 任意 DER 成功样本 | 编码后再解码成功；结果与输入 DER 一致 |
| `fuzz_schema_load` | 任意字节作为描述表（二进制表加载） | 不崩溃、不泄漏；非法表返回错误码 |
| `fuzz_asn1c` | 任意字节作为 `.asn1` 文本（词法/语法入口） | 不崩溃、不死循环、诊断不泄漏 |
| `fuzz_pkix_open` | 任意字节作为 X.509 证书；open + 全部只读访问器 + `find` 路径 | 不崩溃、不泄漏；下标 0/count/SIZE_MAX 与 NULL 输出安全 |
| `fuzz_pkcs_open` | 任意字节依次按 PKCS#1/#8/#10 五种结构 open + 访问器 | 同上 |
| `fuzz_cms_open` | 任意字节按 ContentInfo open，再以 content 打开 SignedData + 访问器 | 同上 |

- 每个 harness 设置内存上限与超时（`-timeout -rss_limit_mb`）；OOM 视为失败。
- 崩溃样本进入 `tests/fuzz/corpus` 或 `tests/fuzz/regressions/` 并纳入常规 CTest（`test_fuzz_smoke` 冒烟）。
- 种子语料按 harness 分目录检入 `tests/fuzz/corpus/<harness>/`，由 `scripts/gen_fuzz_corpus.py` 确定性生成，扩展方式见 `tests/fuzz/README.md`。`schema_load` 语料包含真实 PKIX、PKCS#1/#8/#10 与 CMS 描述表字节；`decode_der` / `decode_ber` / `reader` / `schema_decode` / `roundtrip` 的 DER 种子包含 CMS ContentInfo/SignedData 样本。模块 harness 的 `pkix_open` / `pkcs_open` / `cms_open` 语料只放对应结构的真实样本，并为每份样本派生截断、首字节标签翻转、长度字段 +1 三类变体。
- 本地实测（WSL2 Clang 21.1.8，ASan+UBSan+LSan）：10 个 harness 各短跑 60 s 无崩溃/泄漏/超时；长跑 `fuzz_schema_load` 900 s 亦无发现（迭代数见 README 验证状态表）。新增的 `fuzz_pkix_open` / `fuzz_pkcs_open` / `fuzz_cms_open` 已在 Windows Clang 21.1.0（ASan+UBSan）与 WSL2 Clang 21.1.8（ASan+UBSan+LSan）各跑 60 s，退出码 0；Windows 平台 ASan 不支持 LSan，泄漏检测以 Linux 结果为准。CI 短预算 fuzz job 已把新增 harness 加入 `fuzz.yml` 矩阵。
- AFL++ 作为可替代驱动，不作为基线必选。

### 5.1 语料、覆盖率与差分复跑

语料为确定性生成，均可本地复跑：

```bash
python3 scripts/gen_fuzz_corpus.py           # 各 harness 种子语料
python3 scripts/gen_schema_load_corpus.py    # schema_load 校验分支语料（越界/重叠/重复名/CONSTRAINT/名称表/decimal/tagMode）
```

schema 加载行/分支覆盖率（Clang + llvm-cov）。注意 libFuzzer 输出的 `cov:` 是 trace-pc-guard 的**边（edge）计数**，不是 llvm-cov 的块/分支覆盖率，两者不可直接等同：

```bash
cmake -S . -B build-cov -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DASN1_BUILD_TESTS=ON \
  -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ \
  -DCMAKE_C_FLAGS="-fprofile-instr-generate -fcoverage-mapping" \
  -DCMAKE_CXX_FLAGS="-fprofile-instr-generate -fcoverage-mapping" \
  -DCMAKE_EXE_LINKER_FLAGS="-fprofile-instr-generate"
cmake --build build-cov --parallel

# 检入语料全量（-runs=0 只跑种子，不做随机变异）
LLVM_PROFILE_FILE=cov/corpus_%p.profraw \
  build-cov/tests/fuzz/fuzz_schema_load -runs=0 tests/fuzz/corpus/schema_load/
# 短 fuzz 合并（-max_total_time）
LLVM_PROFILE_FILE=cov/fuzz_%p.profraw \
  build-cov/tests/fuzz/fuzz_schema_load -max_total_time=30 tests/fuzz/corpus/schema_load/

llvm-profdata merge -sparse cov/*.profraw -o cov/merged.profdata
llvm-cov report build-cov/src/CMakeFiles/asn1_static.dir/schema/asn1_schema_table.cpp.o \
  -instr-profile=cov/merged.profdata
```

差分复跑（OpenSSL `asn1parse` 为外部参照，需本机已装 openssl；asn1tools 缺装时该段显式 skipped）：

```bash
cmake --build build --target asn1_dump
python3 tests/differential/diff_asn1.py \
  --asn1-dump build/tests/differential/asn1_dump \
  --report tests/differential/differential-report.md \
  --report-json tests/differential/differential-report.json
```

重新生成后 `git diff --exit-code tests/differential/differential-report.md` 必须无输出；有漂移说明样本或解码行为变化，先归因再更新记录。

## 8. 一期验收标准

一期（BER/DER 解码、DER 编码、C ABI、运行时构树）结束必须满足：

1. 规范向量与错误向量全部通过；差分测试无未解释差异。
2. C ABI 测试用 C99 编译通过，覆盖创建/销毁、错误查询、缓冲区释放、空指针防御。
3. ASan/UBSan 下全部测试无错误；失败注入分配器无泄漏。
4. 至少一个解码 fuzz harness 连续运行 24 小时无崩溃（CI 可用累计替代）。
5. Windows MSVC、Linux GCC、macOS AppleClang 三平台构建与测试通过。
6. 公共头文件在 C99 与 C++17 下均可独立包含；无 C++ 符号泄漏。
7. 文档中承诺的错误码、资源上限、所有权规则均有对应测试。
8. runtime 构树可完成“创建文档 → 创建根/子节点 → 设置值 → 封存 → DER 编码”全流程。

### 9.2 schema 感知解码覆盖率（2026-11-06，WSL2 Clang 21.1.8）

`fuzz_schema_decode` 原先把 schema 建在独立上下文、却用每个输入新建的上下文解码，命中 `schema->ctx != ctx` 前置校验，绑定逻辑实际从未执行（旧 harness 复测仅行 2.31% / 分支 1.78%，`cov: 42`）。本轮改为同一上下文建模，并加入 PKIX 表与一份覆盖全部 kind/约束的小表；语料以能走到深层的合法输入为主，附少量定向畸形样本。检入语料全量（`-runs=0`）+ 30 s 短 fuzz 合并后：

| 指标 | 改前（上轮记录） | 改后 |
| --- | --- | --- |
| 行覆盖 | 23.74% | **90.66%**（931 行中 87 未覆盖） |
| 分支覆盖 | 17.98% | **85.36%**（526 分支中 77 未覆盖） |
| 区域覆盖 | — | **93.05%**（834 区域中 58 未覆盖） |
| 函数覆盖 | 46.43% | **100%** |
| libFuzzer `cov:` 边数 | — | **463**（检入语料 432） |

已覆盖的验证点：SEQUENCE/SET/CHOICE/SEQUENCE OF/SET OF 各分支；EXPLICIT 与 IMPLICIT 标签剥壳（含 IMPLICIT 构造类型与 IMPLICIT SET）；ANY 三形态（裸 ANY、EXPLICIT ANY、缺省）；未知字段保留与 `STRICT_SCHEMA` 报错；DEFAULT 省略；约束 RANGE/SIZE/ENUM/MAX/BIGINT 的通过与失败两侧；`asn1_doc_validate` 的严格/宽松分支；标签不匹配、必需字段缺失、尾随数据、解码器深度限制等错误路径。

剩余 40 个分支点逐类归因：① **本轮范围外**（可经公共 API 覆盖但需额外 schema/场景）：`bindType` 显式包装内层标签不匹配（`expectedTag` 返回 false 的两处）等；② **逻辑死分支/防御性校验**：`typeAt` 越界、`universalTagOf` 的 SEQ/SET 分支（已被 `expectedTag` 提前处理）、`contentSlice` 对已解析节点不可能失败的 TLV 长度校验、`bindType` 的 `element == nullptr`（seal 已拒绝）、字段名重复设置、`integerToDecimal` 的十进制位数容量上限（512 字节幅值最多 1233 位，低于 2048 位上限）、`compareDecimalText`/`parseSmallDecimal` 的空串/非法文本；③ **句柄魔术校验**：`ctx->m_magic`/`m_dead`、`doc->magic && root == nullptr` 只能通过损坏或已释放对象触达，属于防御分支，公共 API 不应构造。②③ 不通过放宽断言覆盖。

### 9.3 覆盖率提升过程中修复的真实缺陷

- `expectedTag` 对 `SEQUENCE/SEQUENCE_OF`、`SET/SET_OF` 无条件返回通用 16/17，导致 IMPLICIT 覆盖的构造类型永远无法匹配标签；现区分“显式剥壳后回到通用标签”与“IMPLICIT 使用类型自身标签”。回归用例见 `tests/c_api/test_schema_decode.c` 第 10 节。
- `evalSimpleConstraint` 只接受 `UNIVERSAL` + tag 2，导致 ENUMERATED（tag 10）与 IMPLICIT 数值字段的 RANGE/ENUM/MAX/BIGINT 约束必然报 `ASN1_E_SCHEMA_CONSTRAINT`；现允许 ENUMERATED 与非通用标签的基本编码数值节点，仅拒绝构造形态。回归用例同上。
