# ASN.1 能力范围

## 1. 范围划分

| 部分 | 定位 | 是否含领域知识 |
| --- | --- | --- |
| 核心 `asn1` | 通用 ASN.1 编解码、DOM、模板机制、内存与错误模型 | 否 |
| 标准模块 `asn1-pkix` / `asn1-cms` / `asn1-pkcs` | 提供标准结构的描述表与模块专用 C API | 是，全部在模块内 |
| 工具 `asn1c` | 解析 `.asn1` 文本、校验、生成描述表 | 否 |

核心不得内置标准结构表，也不得出现证书、密钥、签名算法等概念。标准结构的能力边界由各模块文档定义。

## 2. 核心能力

### 2.1 编码规则

| 规则 | 解码 | 编码 | 阶段 | 说明 |
| --- | --- | --- | --- | --- |
| BER | 支持，含不定长与 EOC | 不单独提供 | 一期 | DER 输出是合法 BER 子集 |
| DER | 支持，严格模式 | 支持 | 一期 | 一期唯一编码目标 |
| CER | 需求触发 | 需求触发 | 不排期 | 只有明确使用场景时重新评估 |
| PER / UPER | 暂不规划 | 暂不规划 | 不排期 | 见 2.6 重启条件 |

不定长验收标准：BER 单层与嵌套不定长解析成功，`tlv_size` 包含 EOC 且 `is_indefinite` 置位；缺 EOC 返回 `ASN1_E_TRUNCATED`；不定长构造的 OCTET STRING、字符串、BIT STRING 可按分段合并取值（BIT STRING 按位累加）；DER 遇不定长或构造内容中的 EOC 返回 `ASN1_E_INDEFINITE_NOT_ALLOWED`；顶层裸 EOC 两种模式均返回 `ASN1_E_MALFORMED_TAG`。

### 2.2 DOM 与模板机制

- **通用 DOM**：无 schema 也能解码、遍历、保留未知字段、回读原始 TLV。
- **模板机制**：核心加载已编译描述表或接收运行时注册，构建同一棵类型树；类型构造性由 `kind` 派生，标签行为由 `tag_mode` 与模块默认标注方式决定；用于字段命名、`OPTIONAL`/`DEFAULT` 判定、`CHOICE` 分支选择、`SEQUENCE OF`/`SET OF` 元素约束与结构化约束校验。
- **约束模型**：约束挂在类型上，字段只引用 `type_id` 并可附加字段级约束；支持值域、SIZE、枚举、MAX/无界、大整数边界与扩展标记。
- **文本边界**：核心不解析 `.asn1` 文本；文本解析只存在于 `asn1c`。
- **两条入口等价**：`asn1_schema_load`（描述表）与运行时注册 API 指向同一类型树，语义一致。

### 2.3 类型与语义读取

| 能力 | 阶段 | 说明 |
| --- | --- | --- |
| 基本类型标签与原始内容 | 一期 | BOOLEAN、INTEGER、ENUMERATED、OCTET STRING、BIT STRING、NULL、OID、字符串族、时间族等 |
| `SEQUENCE`/`SET`/`CHOICE`/`SEQUENCE OF`/`SET OF` | 一期 | 通用 DOM 按标签与子节点遍历；模板感知时按类型树判定 |
| ANY / 开放类型 | 一期 | 描述表 `kind = 6`、schema 注册、保留完整原始 TLV、不结构化展开、`child_count = 0`；支持无包装与 `EXPLICIT` 外层包装两种形态，`content` 在 EXPLICIT 形态返回内层原始 TLV；`SEQUENCE` 中 DEFAULT ANY 必须末位、`SET` 中禁止 DEFAULT ANY；`SET OF ANY` 支持异构解码与 DER 排序回写；编码按 schema 重包装、无 schema 原样回写（允许 BER 字节往返，不保证输出 DER）；节点由 schema 感知解码或 `asn1_node_create_any` 产生，`ASN1_CAP_ANY_OPEN_TYPE` 已置位 |
| `OPTIONAL` / `DEFAULT` | 一期 | 需 schema；通用 DOM 不做模式语义推断 |
| 约束校验 | 一期 | 结构顺序、存在性、标签匹配，以及描述表中的 SIZE/值域约束 |
| OID 点分十进制 | 一期 | 只读文本视图，惰性生成 |
| 大整数只读视图 + 十进制导出 | 一期 | 不做算术；原始字节始终可读；十进制规则见 [C API 规范](02-C-API规范.md) 6.6 |
| UTCTime / GeneralizedTime 结构化只读解析 | 一期 | 解析年月日时分秒、时区偏移与纳秒；时间三态为 `Z`、显式偏移、本地时间（无偏移）；DER 拒绝本地时间形式；不做时区归一或格式化；UTCTime 年份窗口 1950–2049 |
| 字符集转换 | 一期（白名单） | `asn1_node_get_utf8` 先按 `get_raw_string` 规则合并构造形式的各段，再做字符集转换；失败（含合并失败）返回 `ASN1_E_CONVERSION`。支持 UTF8String、PrintableString、IA5String、VisibleString、NumericString、BMPString、UniversalString；白名单外统一报错，T61/Teletex 原始字节走 `asn1_node_get_raw_string` |
| BIT STRING 位级读取 | 一期 | `out_data` 为不含 unused-bits 计数首字节的合并内容；`bit_length = out_size * 8 - unused_bits`；零值 `out_size = 0`、`bit_length = 0`；BER 构造形式合并，DER 零值按 `03 01 00` 校验 |

### 2.4 解码策略与资源上限

- 一期提供整块 buffer 与回调式 reader 两种输入；两者都构建完整 DOM。缓冲区解码通过 `size_t *consumed` 返回实际消费字节数。
- 不提供 SAX/事件式接口；增量 feed 放二期，且仍构建 DOM。
- 解码选项 `flags = 0` 的默认行为：借用输入、按 BER 解码、未知字段**静默保留**、拒绝尾随数据。`STRICT_SCHEMA` 与 `WARN_UNKNOWN_FIELD` 同时设置时严格优先；详见 [C API 规范](02-C-API规范.md) 5.1。
- `asn1_decode_options_t.max_depth` 为 0 时使用上下文默认；非 0 只能收紧，不能放宽。
- 告警由上下文记录，包含 code、offset、depth、字段名与消息；回调返回 `void`，在解码线程内同步调用，告警不影响解码流程、不写入主错误码、也不会中止解码。
- 默认预算：递归深度 64、节点数 1,000,000、输入 64 MiB、输出 256 MiB、告警记录 1024 条；可按上下文配置收紧。
- 对长度、偏移与累计字节做溢出检查；超限返回资源类错误，不继续解析。
- **嵌入式资源分档（本地实测）**：核心 BER/DER 解码（无 schema）`.text` 约 11.5 KB、静态池 16 KB 起，适合小容量 MCU；带 PKIX 描述表 + schema 感知解码的静态池约 85 KB（实测 86,880 字节），需外扩 RAM，不适合 RAM 低于 96 KB 的小容量 MCU。详见 [构建与移植](06-构建与移植.md) 6.4。

### 2.5 约束与结构校验的边界

- 核心校验“ASN.1 结构是否合法”：标签、类型种类、字段顺序、必选/可选、`CHOICE` 分支、`SEQUENCE OF`/`SET OF` 元素类型、描述表中声明的 SIZE/值域/枚举/大整数边界。
- 扩展标记（`...`）建模为类型级可扩展标志与字段级扩展位置；扩展字段按可选处理，未知扩展字段的保留/告警/拒绝由解码选项决定。
- 核心不校验业务语义：证书签名、证书链、有效期策略、密钥用途、吊销状态均不属于核心，也不属于 ASN.1 模块。
- 模块可增加领域级只读辅助，但不得在核心中实现。

### 2.6 PER/UPER 重启条件

PER/UPER 按 schema 推导的定位编码工作，依赖约束求值与定长计算。证书/PKCS 生态统一使用 DER，本场景不出现 PER。仅当出现明确 PER 场景需求（如特定 5G/智能卡项目）时重新评估；重启前必须修订 [ADR-0009](adr/0009-分层与独立模块策略.md) 与 [ADR-0002](adr/0002-编码规则范围.md)。

## 3. 标准模块清单

| 模块包 | 标准结构 | ASN.1 模块来源 | 阶段 | 依赖 |
| --- | --- | --- | --- | --- |
| `asn1-pkix` | X.509/PKIX 证书打开、路径查找与常用字段访问（版本、序列号、签名算法 OID、签名值、issuer/subject 原始 DER、有效期） | RFC 5912：`PKIX1Explicit-2009`、`PKIX1Implicit-2009`、`PKIX-CommonTypes-2009`（来源、勘误与更新链见[描述表格式](11-描述表格式.md)第 15 节） | 一期（已实现） | `asn1` |
| `asn1-pkcs` | PKCS#1、PKCS#8、PKCS#10、PKCS#12 只读结构访问 | RFC 8017、RFC 5208、RFC 2986、RFC 7292 | 二期第一批（PKCS#1/#8、PKCS#10 与 PKCS#12 只读已落地） | `asn1` |
| `asn1-cms` | CMS / PKCS#7 只读结构访问 + `ContentInfo`/`SignedData` 结构构造（写；PKCS#7 归入本模块，不单独建模块） | RFC 6268 的 `CryptographicMessageSyntax2004` 模块（与 RFC 5652 第 12.1 节同构，原文与逐类型对账见 `modules/cms/asn1/`） | 二期第二批（只读、结构构造与写侧结构校验补强已落地，其余结构后置） | `asn1` |
| 自定义模块 | 用户自定义 ASN.1 模块 | 用户提供的 `.asn1` 文本，经 `asn1c` 生成描述表 | 二期加载器 | `asn1` |

- 标准模块必须直接使用公开 RFC 模块，不自创描述格式，也不手写第二份结构定义；输入为自包含展平模块，`IMPORTS` 与参数化仅报诊断。
- 模块各自有独立版本、头文件、C 符号前缀与 CMake 包名；模块之间不互相依赖。
- 第一版所有模块不承担密码学语义：PKCS#8 不解密，PKCS#1 不做 RSA 运算/填充/签名/加密（填充参数仅作 `ANY` 保留），PKCS#12 不解密、不做口令派生、不校验 MAC，CMS 不验签、不摘要、不解密、不校验证书链；`ANY` 字段只返回原始 TLV，由调用方按 OID 二次解析。详见 [ADR-0012](adr/0012-标准模块路线与只读边界.md)。
- **结构构造（写）与只读解析区分**：`asn1-cms` 的 builder 只按 RFC 5652 结构组装节点并输出 DER，不生成签名、不计算摘要、不做加解密、不校验证书链；`CMSVersion`、算法 OID、eContent、签名值与证书/CRL 原始 DER 全部由调用方给值，模块不推导、不校验业务范围。`signedAttrs` / `unsignedAttrs` 原样承载（校验为非空 `SET OF Attribute`，仅改写外层标签），`certificates` / `crls` 校验单 TLV 与分支根标签并按 DER 排序；`sid` 的 `issuer`/`serialNumber` 校验 `SEQUENCE`/`INTEGER` 根标签。结构构造不改变只读边界，新增密码学语义仍需新开 ADR。
- `asn1-cms` 需要的 PKIX 类型（`AlgorithmIdentifier`、`Certificate`/`CertificateChoices`、`TBSCertificate`、`Name`/`RDNSequence`、`Validity`/`Time`、`Extensions` 等 18 个从 `SignedData` 可达的类型）在 CMS 自己的展平模块中复制，不新增 `asn1-cms → asn1-pkix` 依赖；代价是描述表更大、类型重复，需分别对账（见 `modules/cms/asn1/reconciliation.md`）。
- `asn1-pkix` 是一期模板机制的首个验证消费者；已用 RSA 自签、RSA-PSS、EC 自签三张真实证书验收 subject/issuer/validity/extensions 与算法参数三形态，API 见 [C API 规范](02-C-API规范.md) 6.8。
- 模块描述表产物检入各模块 `generated/`（`modules/pkix/generated/`、`modules/pkcs/generated/`、`modules/cms/generated/`），默认构建无需 `asn1c`；`-DASN1_PKIX_REGENERATE_TABLE=ON` / `-DASN1_PKCS_REGENERATE_TABLE=ON` / `-DASN1_CMS_REGENERATE_TABLE=ON` 在构建期重新生成并与检入产物逐字节比对，差异即构建失败。表随模块发布，模块内部不手写 ASN.1 结构。

## 4. 工具 asn1c

| 能力 | 阶段 | 说明 |
| --- | --- | --- |
| 解析 `.asn1` 文本 | 一期 MVP | 词法、语法、基础语义检查 |
| 基本/构造类型与标注方式 | 一期 MVP | 基本类型、SEQUENCE/SET/CHOICE/SEQUENCE OF/SET OF、模块级与类型级标注 |
| 约束与扩展标记 | 一期 MVP | 值域、SIZE、枚举、MAX、大整数边界、`...` |
| 输入形态 | 一期 MVP | 一期输入是**自包含展平模块**（如 `modules/pkix/asn1/PKIX-Flattened-2009.asn1`），不依赖跨模块引用 |
| `IMPORTS` | 二期 | 一期遇到即报 `ASN1C_E_IMPORT_UNRESOLVED`(9007)；直读原始 RFC 模块留二期 |
| 单参数参数化实例化 | 二期 | 一期遇到报 `ASN1C_E_UNSUPPORTED_CONSTRUCT`(9006)；参数化展开留二期 |
| `CLASS` / `WITH SYNTAX` / 信息对象集 | 一期采用预展开模块，直接解析留二期 | 仓库已产出展平模块（见[目录说明](../modules/pkix/asn1/README.md)），原版 RFC 5912 保留作参考；一期遇到这些构造报明确诊断 |
| 生成描述表 | 一期 MVP | 输出 C 源数组或二进制资源，含名称表（命名位/数值名），布局见[描述表格式](11-描述表格式.md) |
| 诊断输出 | 一期冻结 | 固定 `<file>:<line>:<column>: <severity>: <code>: <message>` 与错误码表 |
| 增量校验与更多输出形态 | 二期 | 更完整的语义校验、可选输出格式 |

工具独立构建、独立版本；版本由 `tools/asn1c` 的 `project(... VERSION ...)` 生成 `asn1c_version.h`，`asn1c --version` 输出该版本字符串，源码中不手写版本号。核心不链接工具，工具也不进入核心 ABI。

## 5. 明确不做

- 核心内置 X.509/PKIX/CMS/PKCS 结构表。
- 用户可写的私有 schema DSL；唯一事实来源是公开 ASN.1 模块。
- 签名验证、证书链构建、有效期策略、吊销检查。
- 大整数算术、时区归一。
- 字符集白名单之外的无损转换（如 T61/Teletex 到 UTF-8）。
- 一期增量 feed、SAX/事件式解析。
- PER/UPER 固定排期；CER 固定排期。
